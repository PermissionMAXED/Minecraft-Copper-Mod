# COPPER INFERNO 1

A Minecraft **Fabric** mod (author: Sonic0810) for **Minecraft 1.21.9** (the "Copper Age", which ships the vanilla Copper Golem). v4 "mega content update" scale: **1291 blocks** (blockstates), **~1874 item definitions**, **102 mobs + 20 bosses** (122 entity loot tables), **~50 worldgen features**, **2218 recipes**, the `copper_inferno:inferno` dimension (5 biomes, incl. `verdigris_jungle`), oxidizing copper armor & tools, a copper player statue, Dr.Pepper brewing with a DOOM kick, Dr.Pepper golems, and an in-game handbook with an auto-generated all-recipes index.

Key v4 structure:
- **Creative tabs**: `main` and `blocks` plus 4 v4 tabs — `chromatic`, `depths`, `gems`, `fauna` (`core/ModCreativeTab.java`; icon items resolve lazily since tabs register before feature items).
- **`core.content` registrars**: bulk wrappers that register whole families from ONE call — `WoodSets.registerWoodSet` (full wood family), `PaletteSets.registerPaletteSet` (20-block stone palette), `AlloySets.registerAlloySet`, plus `Content*Block` helper classes. Feature packages call these instead of registering each block by hand.
- **Wrapper-registration audit rule**: `devtools/audit_assets.py` check (f) statically expands wrapper calls (e.g. `registerPaletteSet("foo", ...)` ⇒ 20 derived ids) to verify every registered id has items/blockstates/models/loot. Call sites MUST pass a **string literal** (never a variable) as the leading id/palette argument, or the audit cannot resolve the ids.
- **Handbook recipe_index pipeline**: `devtools/gen/handbook_index_gen.py` walks `data/copper_inferno/recipe/**` and emits `assets/copper_inferno/handbook/recipe_index.json` (one line per recipe, `grid9` layout contract) which the client `HandbookRecipeIndex` loader reads. Re-run it after ANY recipe change; it exits non-zero on unknown recipe types or unmapped `#tag` ingredients (extend `TAG_REPRESENTATIVES` for new tags).

Asset/data pipeline (all Python 3, stdlib only, idempotent):
- Generators: `devtools/gen/<package>_gen.py` (one per content package) write textures/models/blockstates/loot/recipes AND lang fragments (`assets/copper_inferno/lang/fragments{,_de}/*.json`) and tag fragments (`devtools/tagfrag/*.json`) — they do NOT touch the merged runtime files.
- Merge steps: `devtools/merge_lang.py` (and `--locale de_de`) builds `en_us.json`/`de_de.json` from fragments (never hand-edit the merged files; the branding key `itemGroup.copper_inferno.main` must stay `"COPPER INFERNO 1"`); `devtools/merge_tags.py` builds `data/minecraft/tags/**` from `devtools/tagfrag/`.
- Validators (must all be green before committing content changes): `devtools/audit_assets.py`, `devtools/check_tags.py`, `devtools/check_handbook.py`, `devtools/check_de_coverage.py`, `devtools/check_recipe_collisions.py`.

## Cursor Cloud specific instructions

Environment: Java 21 + Gradle (via the committed `./gradlew` wrapper, Gradle 8.14) + Fabric Loom 1.13.6. **Yarn mappings** (`1.21.9+build.1`) are used, NOT Mojang mappings — vanilla classes/methods use Yarn names (e.g. `net.minecraft.item.Item`, `Item.Settings`, `Identifier.of`).

Standard commands (see `build.gradle` / `gradle.properties`):
- Build: `./gradlew build --no-daemon` (produces `build/libs/copper-inferno-<mod_version>.jar`).
- Dedicated server smoke test: `echo "eula=true" > run/eula.txt` then `./gradlew runServer --no-daemon`. Great for verifying registrations, recipes, loot tables, `/give`, `/summon`, `/setblock` — do this for any content change.

Non-obvious gotchas:
- **Only ONE Gradle `run*` task can hold the `run/world` session lock at a time.** A second concurrent `runServer` fails with `SessionLock$AlreadyLockedException`. Stop the running one first, or launch a second instance from a different run dir.
- **Client (`./gradlew runClient`) works headless only via software OpenGL.** Use: `DISPLAY=:1 LIBGL_ALWAYS_SOFTWARE=1 GALLIUM_DRIVER=llvmpipe MESA_GL_VERSION_OVERRIDE=4.6 ./gradlew runClient --no-daemon`. It reaches the title screen and is playable but SLOW (llvmpipe). Audio init fails harmlessly (`Failed to open OpenAL device` / ALSA errors) because the VM has no sound card — this is expected, not a bug. Client-only visuals (statue renderer, motion-blur post effect, DOOM proximity audio, particle factories) can only be verified with a client.
- **Inspecting the 1.21.9 + Fabric API in Yarn names** (there are no offline javadocs): `javap` against Loom's remapped jars. Minecraft: `~/.gradle/caches/fabric-loom/minecraftMaven/net/minecraft/minecraft-{common,clientonly}/1.21.9-*/*.jar` (exclude `*backup*` / `*intermediary*`). Fabric API (yarn-named): `/workspace/.gradle/loom-cache/remapped_mods/**/fabric-*.jar`. The APIs changed a lot vs older 1.21.x (e.g. items need a registry key + a `assets/<ns>/items/<id>.json` model-definition file in addition to `models/item/<id>.json`; `BlockEntity` uses ReadView/WriteView NBT; block-entity renderers use the new `createRenderState`/`updateRenderState`/`render(state, MatrixStack, OrderedRenderCommandQueue, CameraRenderState)` contract; `GameRenderer.setPostProcessor` is private). Always verify a signature with `javap` before using it.
- **Content changes go through the generator pipeline, not by hand.** Edit/extend `devtools/gen/<package>_gen.py`, re-run it, then re-run `devtools/gen/handbook_index_gen.py`, `devtools/merge_lang.py` (both locales), `devtools/merge_tags.py`, and the five validators (all listed in the intro). Generators are idempotent — `git status` after a full regen should show only your intended changes.
- **New blocks registered via the `core.content` wrappers** (`WoodSets`/`PaletteSets`/`AlloySets`) must pass a string-literal id as the first argument, or `audit_assets.py` check (f) fails to expand the call and reports the derived ids as unregistered/missing.
- **Server-console smoke testing on an empty dedicated server**: set `pause-when-empty-seconds=-1` in the gitignored `run/server.properties` and `/forceload add` the test area, otherwise the server pauses ticking and entity selectors (`@e`) match nothing. `/give @p` fails with "No player was found" when no player is online — instead prove item registration with `/item replace entity` on a summoned armor stand (any item fits `weapon.mainhand`; `armor.*` slots reject non-equipment). Dimension check without a player: `/execute in copper_inferno:inferno run setblock ...` + `/execute in copper_inferno:inferno run locate biome copper_inferno:verdigris_jungle`. Summon bosses AWAY from sample fauna — bosses kill nearby test mobs within seconds.

Code layout: split source sets — common code in `src/main/java`, **client-only code in `src/client/java`** (client resources in `src/client/resources`). Features live under `net.sonic0810.copperinferno.feature.<name>` and are wired from `CopperInferno` / `CopperInfernoClient`; shared registries + the item-oxidation engine live in `net.sonic0810.copperinferno.core`; the v4 bulk registrars live in `net.sonic0810.copperinferno.core.content`.
